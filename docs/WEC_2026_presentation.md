## Page 23

📈 3. Key Findings and Conclusions
🔹 Positional physical trends:
• Central and defensive midfielders (CM, DM): exhibit the highest
total distance covered (~11.4–11.9 km).
• Wing-backs and full-backs (WB, FB): Recorded the highest HSR and
sprint distances (~1200–1500 m).
• Centrer-backs (CB): Demonstrated the lowest total distance
covered and overall locomotive intensity (~9.7–10.1 km, HSR < 800
m).
• Attacking midfielders (AM): intensity > total volume (the highest
frequency of offensive actions).
• Forwards (FW): in two-striker systems (FW2) significantly greater
physical intensity compared to those in a lone-forward role (FW1).
🔸 Technical and Tactical Performance Indicators:
•Most passes: defensive midfielders (DM).
•Most dribblings and penalty area penetration: wingers (WF) and
attacking midfielders (AM).
•Most tackles: center-backs (CB).
🧪 Practical Implications
✅ Position-specific training programs should be
designed to reflect:
•Differentiated volume and intensity based on specific
positional requirements.
•Match-Critical Phases (e.g., peak 1-minute intensity
intervals).
•Technical-T0actical Context and individual player tasks
(e.g., overlapping WB vs static CB).
📌 These findings provide a framework for designing
evidence-based, position-specific training protocols
derived from elite-level match data.
Chen S, Zmijewski P, Bradley PS. Biol
Sport. 2025;
doi:10.5114/biolsport.2025.148535.

A few words about the competition strategy (2/5)
Data Preparation
1. Identify Relevant Data Sources: Start working on data from the very beginning. Work with
transferable formats.
2. Data Cleaning and Preprocessing: Ensure that the data is clean and formatted correctly.
This includes handling missing values, removing duplicates, and normalizing data types.
Utilize tools like Pandas, dplyr or Excel for efficient data manipulation.
3. Data Exploration: Conduct exploratory data analysis (EDA) to understand the data's
characteristics. Visualizations can help identify trends, patterns, and anomalies that may
inform your solution.
4. Documentation: Keep information about main decisions about data sources, preprocessing
steps, and any assumptions made during the data preparation phase. This will be invaluable
for both the MVP and paper writing stages.

## Page 53

A few words about the competition strategy (3/5)
MVP Solution
1. Define the Core Problem: Clearly articulate the aims of the research,
hypothesis, goals. This will guide the development of your Minimum Viable
Product (MVP).
2. Focus on Essential Solution: Identify the key approaches/models that will
demonstrate the viability of your solution.
3. Iterative Development: Use an agile approach to develop your MVP. Start
with a basic version and iteratively extend the approach.
4. Deliveries check-list: Address all main research questions, iteratively
consider the additional ones.

## Page 54

A few words about the competition strategy (4/5)
Extra Solution
1. Identify Additional Features: Once the MVP is established (but not
developed), brainstorm additional features that could enhance the user
experience or provide more value.
2. Prioritize Based on Impact: Evaluate which extra features would have the
most significant impact and are feasible within the hackathon timeframe.
3. Allocate Team Roles: Assign team member(s) to work on extra features.

## Page 55

A few words about the competition strategy (5/5)
Paper Writing
1. Outline the Structure: Start with a clear outline that includes sections such as
Introduction, Data, Methodology, Results, and Conclusion. This will provide a roadmap
for your writing.
2. Collaborative Writing: Utilize collaborative tools like Google Docs to allow all team
members to contribute to the paper. Assign sections based on individual strengths to
streamline the writing process.
3. Focus on Clarity and Conciseness: Write clearly and concisely. Avoid jargon unless
necessary, and ensure that complex ideas are explained in an understandable manner.
4. Cite Sources and Acknowledge Contributions: Properly cite any data sources,
frameworks, or tools used in your project.

## Page 57

Will you score a goal?
Case study – predicting goalscoring probability
(UEFA U21 2025)

## Page 58

Coaches trust intuition. It works - but:
● ignores subtle performance patterns,
● misses interactions & context,
● is hard to compare objectively.
A data-driven approach enables a more objective, systematic
and reproducible evaluation of player performance.
Aim: 👉 Build a predictive model to support coaches in better assessing a
player’s likelihood of scoring a goal over the remaining duration of the game
Task  description - Main Aim (1/4)

## Page 59

Task  description - What Data Do We Have? (2/4)
Tournament: UEFA U21 EURO 2025 (Slovakia)
Match broken into:  15-minute intervals
Features:
● rolling last_15 and cumulative features
● supplementary datasets that include event-level data
(shots, runs, pasess and actions under pressure)
Target variable: SCORED_AFTER (goal 1 = yes / 0 = no)

## Page 60

Task  description - Research questions? (3/4)
The main research questions guiding this case are:
RQ1: How well player’s on-field behaviour during a match
can predict the probability that they will score a goal later
in the game (measured by balanced accuracy, AUC)?
RQ2: Which aspects of a player’s on-field behaviour
during a match determine the probability that they will
score a goal later in the game?

## Page 61

Task  description - Research questions cont? (4/4)
To gain deeper insights, several more detailed research questions can be formulated and addressed:
RQ3: Is information about sprints and shots alone sufficient to accurately predict the probability of a player
scoring a goal?
RQ4: Does incorporating passing data or information about player behaviour under defensive pressure
improve the predictive performance of goal-scoring models?
RQ5: Does short-term performance (recent 15-minute activity) or cumulative performance up to a given
point in the match have stronger influence on the probability of scoring a goal?
RQ6: Does an increase in short-term performance intensity relative to a player’s overall performance level
increase the probability of scoring a goal?
RQ7: Do external factors that are not directly controlled by the player influence the probability of the
player scoring a goal, and if so, which of them matter most?

## Page 62

Data description
There are five datasets representing various aspects  of players’ activity.
The main dataset for the contest:
● players_quarters_final.csv (3 486 rows) – player activity snapshots at match quarter-
hour checkpoints
Source and supplementary datasets:
● player_appearance_pass.csv  (29 795 rows) – individual pass events
● player_appearance_behaviour_under_pressure.csv (12 185 rows) – passes made
while being pressed
● player_appearance_run.csv (35 133 rows) – high-speed run / sprint events
● player_appearance_shot_limited.csv (780 rows) – individual shot events

## Page 63

Data description – main dataset for the contest
● covers 31 matches and 869 unique player appearances
● each row represents one player at one time checkpoint, capturing their
activity both in the preceding 15-minute window and cumulatively from
the start of the match up to that point
● the binary target variable scored_after indicates whether the player
scored a goal at any point after the checkpoint in the same match,
excluding own goals
● constructed by aggregating event-level data from selected source tables
(player_appearance_shot_limited.csv and player_appearance_run.csv)

## Page 64

Data description – main dataset for the contest
Observation unit and time structure
● checkpoints defined within match periods, with minutes counted locally
from the start of each period
● up to seven checkpoints per match: minute 15, 30, and 45 of the first half
(H1_15, H1_30, H1_45), minute 15 and 30 of the second half (H2_15, H2_30),
and – for matches that reached extra time – minute 45 of the second half
(H2_45) and minute 15 of the first extra time period (ET1_15)
● only players who were actively on the pitch at the moment of the
checkpoint are included, identified through the continuous minute_in and
minute_out columns

## Page 65

Data description – main dataset for the contest
Feature groups
● variables with the prefix last15_ describe the player’s activity
in the 15-minute window immediately preceding the checkpoint
● variables with the prefix cumul_ describe their accumulated activity
from the start of the match
● both groups cover the same two domains: physical exertion
(derived from player_appearance_run.csv) and shooting
(derived from player_appearance_shot_limited.csv)
● Goals scored prior to the checkpoint were excluded from the shot features
to prevent information leakage into the target variable

## Page 66

Data description – main dataset for the contest
Target variable
● scored_after is a binary indicator equal to 1 if the player scored
at least one non-own goal after the checkpoint in that match,
and 0 otherwise
● the target is heavily imbalanced: 203 positive cases
out of 3,486 observations (approximately 5.8%), reflecting
the natural rarity of goalscoring events in football

## Page 67

Data description – source and supplementary data
