# Cleaning Rules

This document was generated by `src/python/data_quality_audit.py`.

## Core Rules

1. Standardize missing-value tokens (`NULL`, empty strings, etc.) to a single NA representation.
2. Enforce stable column dtypes (booleans, numerics, categories, datetime) before auditing/modeling.
3. Preserve uniqueness of primary event IDs (`id`) where present.
4. Keep key integrity for all `*_player_appearance_id` links.
5. Enforce range/consistency constraints: non-negative distances/speeds, minute bounds, and checkpoint consistency.
6. Keep `scored_after` strictly binary (0/1).

## Modeling Scope Policy (Checkpoint Task)

1. Use `players_quarters_final.player_appearance_id` as the canonical modeling ID set.
2. For supervised checkpoint modeling, filter event-table rows to canonical IDs only.
3. Keep unfiltered event tables as separate reference datasets for descriptive/event-only analyses.
4. Persist kept/dropped counts and percentages for each event table in a scope report artifact.
5. Any downstream feature-generation script must consume only scope-filtered event tables for modeling outputs.
