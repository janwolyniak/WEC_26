# Evaluation Protocol Note

This note was generated by `src/python/split_strategy.py`.

## Frozen Split Strategy

- Fixture-grouped final holdout size: 6 fixtures.
- Development size: 25 fixtures.
- Development CV: 5-fold grouped cross-validation by `fixture_id`.
- Split artifacts are fixed on disk and must be reused across all experiments.
- Holdout fixtures remain untouched until final model freeze.
- If explicit team IDs are unavailable, team balance is monitored via the documented `fixture_id + is_home` proxy together with player-composition diagnostics.

## Metric Policy

- Primary model-selection metric: mean development-fold Balanced Accuracy.
- Secondary metrics reported for every experiment: ROC AUC, PR AUC, and Brier score.
- Fold-wise metrics must be archived to support uncertainty intervals and paired ablation comparisons.

## Fixed Vs Tunable

- Fixed: split assignments, random seed, grouped evaluation protocol, no holdout access during development, and fold-contained preprocessing/feature engineering.
- Tunable later: model family, regularization/class-weight settings, tree depth/learning-rate style parameters, and approved feature-set variants.
- Forbidden: regrouping fixtures, peeking at holdout performance during tuning, or fitting preprocessing on combined train+validation data.

## Leakage Guardrails

- Every training fold must exclude validation fixtures completely.
- All feature engineering, imputation, encoding, scaling, and calibration must run inside the active training fold only.
- Temporal leakage findings from `docs/leakage_checklist.md` remain binding for downstream modeling tables.
